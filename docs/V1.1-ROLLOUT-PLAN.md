### Two corrections the batch needed

Both were path errors from a tree laid out differently to this one. Worth
recording, because applying the batch as delivered would have failed in two
opposite ways.

**1. The route wiring targeted dead code.** Every server phase shipped
`api/routes/index.js`. Nothing requires that file — the container runs
`node dev-server.js`, which loads `api/index.js` — and it cannot resolve its
own siblings from where it sits, so it has been dead since the entry moved.

- Applied as delivered: the calendar routes mount on nothing. The feature
  would appear installed and do nothing. This is exactly what the earlier
  phase-5-only extraction produced.
- Copied over the live entry instead: that file is 160 lines against the live
  entry's 570, and would have dropped **request logging, the process
  handlers, `ALLOW_LOCALHOST_ORIGIN`, HSTS, `nosniff`, `x-powered-by`, the
  webhook monitor and `lib/app-url`** — including the flag that stopped local
  dev and the super-admin panel breaking once already.

So the calendar wiring was ported into `api/index.js` by hand: two raw-body
receivers beside the Resend webhook (Calendly signs the exact bytes), and
three `safeMount` calls above the generic `/api` route, with
`business-groups` first so the `":provider"` parameter cannot capture it.

**2. Eight requires were one level short.** `business-groups.js` and
`internal-calendar.js` reached for `../lib` and `../middleware`; from
`api/routes/` those resolve nowhere. `safeMount` caught both at boot and
mounted 503 placeholders rather than failing the container — which is the
whole reason it exists. Fixed to `../../`.

Also: `agently-ws-server/test/run.js` required only `billing-tracker`, so the
`calendar-tools` tests shipped with the batch would never have run. Registered.

### The migrations are additive — verified

Five new tables, and nothing else:

```
calendar_integrations     create table if not exists
appointments              create table if not exists
oauth_start_nonces        create table if not exists
business_groups           create table if not exists
business_group_members    create table if not exists
```

The only `alter table` statements drop a check constraint on `appointments`,
which migration 1 creates. **No migration touches any table production
already has.** All five new tables get `enable row level security` with zero
policies — fail-closed, so the anon key reads nothing and the service role
(which the API uses) is unaffected. That matters because `appointments`
carries `attendee_name`, `attendee_email` and `attendee_phone`: it is the
same shape of data as the N015 exposure, with the opposite posture.

### 3. Daily scheduler

```
POST https://<api>/api/internal/calendar/sweep
header: x-agently-internal-secret: <INTERNAL_API_SECRET>
```

Renews Google watch channels expiring within 24h. Without it, Google push
sync degrades silently after a week.

### 4. Google verification

`07-google-verification-prep/` in the batch has the click-by-click package.
Nothing is submitted, so the 3–6 week clock has not started. Testing mode
works meanwhile: up to 100 test users, ~7-day tokens, unverified-app warning.
Calendly needs none of this, which is why the booking engine is Calendly-first.

## One loose end worth closing

`agently-server/api/routes/index.js` is still there, still dead, still a
5,377-byte duplicate of an app entry that moved. It is what sent this batch's
route wiring into the void, and it will do the same to the next one. It was
left untouched rather than deleted, because deleting a tracked file is your
call — but it has no callers and cannot resolve its own requires.
